# REN-104 and REN-105 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add recoverable App Router boundaries for purchase flows and safely reduce two unnecessary client boundaries.

**Architecture:** A shared client recovery component logs only a route marker and Next digest, then renders safe retry/navigation UI. Checkout and cart use storefront loading/recovery shells, orders relies on its existing layout, and the root global error owns `<html>`/`<body>`. The client-boundary pilot only removes directives from two stateless Radix wrappers.

**Tech Stack:** Next.js App Router, React 19, Radix UI, Bun test.

**Spec:** `docs/.work-items/REN-104/SPEC.md`; `docs/.work-items/REN-105/SPEC.md`

## Global Constraints

- Do not alter payment, order, cart, inventory, API, or webhook behavior.
- Error output/logging must contain only a boundary marker, route segment, and Next digest.
- Boundary reset must not auto-retry payment/order mutations.
- REN-105 is limited to `separator.tsx` and `label.tsx`; server consumers pass only serializable props.
