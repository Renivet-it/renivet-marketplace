## Gate 20 — AI call economics (mandatory dedup discipline)

| Task | Dedup unit | Not this |
|---|---|---|
| Schema/column mapping | Once per unique source column, per brand — cached indefinitely once confirmed (never silently regenerated by a later call, matching the existing `SCHEMA_MAPPING.md` design) | NOT once per row |
| Attribute normalization | Once per distinct unresolved value, written into a per-brand-scoped lookup table (correcting the earlier cross-project-critique-flagged global-scoping gap) | NOT once per row |
| SKU candidate ranking | Only for genuinely ambiguous candidates that fail the deterministic waterfall — and even then, queue-only, never a write | NOT once per row, NOT once per product |
| Anomaly/error explanation | Only when a deterministic detector has already fired | NOT proactive/speculative |

This discipline is what keeps the ESTIMATED-low cost bound credible even without knowing exact brand-tier distribution — cost scales with distinct ambiguity, not with catalog size.

## Gate 19 — Zero-infrastructure option

**Yes, P08 V1 can work with ZERO new AI infrastructure.** Baseline: deterministic mapping (alias dictionary + normalized-exact match) + saved/pinned mappings (confirmed once, reused forever per brand) + lightweight matching (exact `sku`/`barcode`/normalized-title+attributes) + manual review for anything unresolved.

**Value lost vs. the AI-assisted version:** not a capability loss — everything remains achievable. The cost is **onboarding friction**: a brand with unusual column headers or messy attribute values does 100% of the mapping manually on first upload instead of getting a suggested mapping to confirm. This matches the original P08 research's own framing (schema-mapping AI-assist was already cleared as "the single richest AI use case in the whole program," but as a friction-reducer, not a capability-enabler).

**Recommendation:** given Option E's incremental cost is low and already cleared by two independent critique passes (the original research's `AI_CRITIQUE.md` and this portfolio's `AI_GOVERNANCE.md`), **include the hosted-LLM assist in V1** rather than deferring to a "V1.1" — the zero-infra path remains available as a fallback if leadership specifically wants the leanest possible first slice, but is not the default recommendation.
