# V2 — P01

V2 = capability that requires new data or new decisions that don't exist yet. Nothing in V2 is scheduled; each item has an explicit trigger, not a date.

## REN-167 — Typo-tolerant local search fallback (pg_trgm)
- **Trigger:** REN-146 ships, accumulates fallback-activation-rate data (how often ILIKE fires and what those queries look like), and that data shows a meaningful share of failed/typo'd searches would benefit from fuzzy matching. **DECISION REQUIRED**: what threshold of fallback-activation counts as "meaningful" — not decidable now.
- **Why deferred, not built now:** No data exists to justify the added query complexity; `pg_trgm` indexing has its own cost (index size, write-path overhead) that isn't worth paying speculatively.

## Fallback-source logging (extension beyond REN-154's literal scope)
- **Trigger:** Whoever implements REN-154 decides to include it (recommended, see `05-algorithms/DECISION_LOGIC.md`) — if not included then, this becomes a V2 item triggered by "REN-167 evaluation requires it and it wasn't captured in V1."

## Search-to-purchase conversion measurement
- **Trigger:** P06 (Measurement & Experimentation) has a mechanism to link search events to order events. This Epic does not build that link itself — see `07-feasibility/DEPENDENCIES.md`'s cross-Epic note.

## Any ranking-quality experimentation (e.g. tuning the 0.28 brand-match threshold, RAG `limit` parameter)
- **Trigger:** REN-154's data shows a specific, named ranking-quality problem (e.g. a measurably high zero-result rate, or a measurably low click-through rate on top results) — not before. See `09-validation/EXPERIMENT_STRATEGY.md`.
