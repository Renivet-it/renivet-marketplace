# V2 — P08

V2 = exactly the research's Phase 2 components, each gated on its own named trigger (see `VERSION_TRIGGERS.md` for the authoritative trigger list — do not invent new ones). V2 is not a date-scheduled release; it is whichever of the following components has an evidenced, fired trigger first.

## Generalized API-First tier

Generalizes the existing Unicommerce connector pattern into a reusable abstraction serving additional API-capable brands. **Trigger**: a second, named, API-capable brand is actually onboarding. Not building this ahead of that trigger avoids generalizing a pattern with only one real instance to generalize from. (Research: `14-critic/ANTI_OVERENGINEERING.md` Component 2.)

## Scheduled-File tier

Polling/scheduled pull of brand-hosted files, rather than manual upload. **Trigger**: specific brands report manual-upload cadence as active friction. Named in research as "the weakest justification for new engineering of any component" — a convenience gap, not a capability gap, since the brand can already upload manually at the same cadence at zero extra cost; a missed scheduled pull with no one watching is a worse silent-failure mode than a missed manual upload (which the brand notices immediately). (Research: `03-alternative-architectures/`, `14-critic/ANTI_OVERENGINEERING.md` Component 3.)

## Full reconciliation / confidence-review spine

Detect-and-report drift across a full data set on an independent cadence, with categorization (value mismatch / missing-in-Renivet / missing-in-source / stale-since), a report artifact, and a human action path. **Trigger**: a second live source per brand needing reconciliation. Depends on the historical inventory log and event-style audit trail deferred in `06-data/DATA_REQUIREMENTS.md` (Option C/D). (Research: `06-sync-and-reconciliation/RECONCILIATION.md`; `15-synthesis/SYNTHESIS.md` §3.)

## `brand_external_identifiers` multi-source identity table

A dedicated mapping table (`id, brand_id, product_variant_id, source_system, identifier_type, identifier_value, confidence, resolved_at, is_active`) for brands with more than one live source needing reconciled identity. **Trigger**: a brand has two concurrent live sources needing reconciliation. Also a precondition for any future SKU-matching auto-apply (see V3). (Research: `05-identity-and-mapping/SKU_IDENTITY.md` §4.)

## Sequencing note

These four components are independent of each other — none blocks another, and none is prioritized over another by a fixed order (this corrects `HYBRID.md`'s original build order, which sequenced Scheduled-File ahead of being deprioritized by the critic pass). Whichever trigger fires first is built first.
