# V3 — P08

## SKU-matching AI auto-apply

Re-enabling any form of the originally-proposed Tier 2 ("corroborated fuzzy → auto-apply, audit-sampled") behavior, corrected in `05-algorithms/DECISION_LOGIC.md`.

**Trigger, quoted exactly from the research, all three conditions required**: "(a) real match data exists to validate the 0.90/0.75 thresholds against actual false-positive/negative rates, (b) the minimal provenance extension ships, and (c) `brand_external_identifiers` pin-once persistence is enforced in code so a corrected/confirmed match is never re-guessed by the fuzzy path on a later sync." (Research: `15-synthesis/SYNTHESIS.md` §2.)

Precondition (b) ships in V1. Precondition (c) is a V2 component (`brand_external_identifiers`, gated on its own trigger — a brand with two live sources). Precondition (a) requires real match data, which V1's logging design generates as a byproduct but which only becomes usable once enough volume has passed through the suggest-only queue (`05-algorithms/ALGORITHM_EVALUATION.md`).

**This means V3 cannot happen before V2's `brand_external_identifiers` component exists** — V3 is not simply "later in time," it is structurally dependent on a specific V2 component, which is itself gated on its own independent trigger. If that V2 trigger never fires, V3 never becomes eligible either.

## Why this is placed at V3, not V2, even though it's "AI work" like V1's AI-assist features

V1's AI-assist features (schema mapping, attribute normalization) are narrow, human-confirmed, and low-blast-radius by design — they do not carry the same guardrail weight as identity/SKU auto-apply, which BRule-1 treats as a hard rule, not a tunable rollout stage. Grouping SKU-matching auto-apply with V1's other AI work would understate how much stronger its evidentiary bar is.

## Nothing else is currently named for V3

No other component in the research program is described as depending on a V2 component's completion. This file is intentionally short — it names one thing because the research names one thing at this dependency depth.
