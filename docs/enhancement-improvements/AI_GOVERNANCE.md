# AI Governance

Portfolio-wide principles for any AI use case in the Enhancement & Improvements program. **Not a new framework** — this generalizes the guardrail design P08's research already built and adversarially tested (`docs/research/brand-commerce-integration/08-ai-opportunities/AI_GUARDRAILS.md`, `14-critic/AI_CRITIQUE.md`), so future AI use cases (in any Epic) start from a proven pattern instead of reinventing one per project.

## Principles

1. **Deterministic/rules-first, always.** Before proposing an AI use case, show the deterministic or statistical alternative and why it's insufficient — this is the anti-overengineering gate (`PORTFOLIO_ANTI_OVERENGINEERING.md`), applied specifically to AI. P08's own audit found its best-designed AI use cases (schema mapping, attribute normalization) already do this correctly; its weakest (SKU-matching auto-apply) didn't, and that gap was caught and fixed by exactly this discipline.
2. **Don't use paid external LLMs by default for product features.** Compare local/self-hosted/reusable models and cost/latency before committing to a paid API dependency for any recurring, high-volume product surface. This program found no current Renivet product AI use case running at volume yet — the principle is prospective, not correcting an existing violation.
3. **Confidence tiers gate what auto-applies, not what runs.** AI can *run* freely to produce a suggestion; whether that suggestion *writes* without a human depends on a confidence tier with real, independently-validated thresholds. P08's `AI_CRITIQUE.md` found a real violation of this principle mid-program (a design that let "corroborated fuzzy" SKU matches auto-apply, contradicting the project's own hard guardrail) — caught by adversarial critique, not by the confidence design itself. **Any future AI use case must be reviewed by someone who did not design it before its confidence tiers are trusted.**
4. **Hard-boundary fields never auto-apply, at any confidence.** Inventory quantity, price, tax, warehouse/tenant identity, final SKU/product identity, order state, financial state — AI proposes, never silently writes, for any of these. This list is inherited directly from P08's guardrail design; extend it per-Epic only with equal rigor, never loosen it.
5. **Log model version and material inputs/outputs.** Any AI call that influences a stored value must be traceable to what model produced it and what it saw — this is the same provenance discipline `RECOMMENDED_ARCHITECTURE.md` requires for data ingestion generally (source + timestamp), applied to AI-influenced writes specifically.
6. **Define fallback, monitoring, and rollback before shipping, not after.** REN-146/147 (the existing external ML/search microservice has no timeout and a fallback that hits the same host as its primary call) is the cautionary example already in the portfolio — an AI/ML dependency without a real fallback degrades silently to nothing on outage. Every future AI use case should name its fallback and who's monitoring it as part of its SPEC (`AGILE_PROJECT_LIFECYCLE.md`), not as an afterthought.
7. **Human review is a named, owned role, not an assumption.** P08's business critique found this precondition unresolved even for its own (not-yet-built) design: nothing in the portfolio currently confirms Renivet has staffed or assigned ownership of an AI-suggestion review queue. Any Epic proposing an AI use case with a review-queue component must name the reviewer/owner in its SPEC, or explicitly flag it as an open question (see `07-decisions/`) rather than assume it will be staffed.
8. **One AI-assist pattern reused, not one per Epic.** Do not let each Epic build an independent AI stack (own prompt scaffolding, own confidence model, own guardrail list). P08's `AI_GUARDRAILS.md`/`CONFIDENCE_MODEL.md` pattern is the reference implementation — new Epics should extend it, not duplicate it.

## Current state

No product AI use case beyond the external ML/search microservice (a third-party dependency, not Renivet-owned — see `ML_AI_LIFECYCLE.md`) and P08's not-yet-implemented AI-assist design is live in Renivet today. This document exists to keep the next one disciplined, not to govern something already running unsupervised.
